# 네트워크 장비 설정 검증 (Network Config Validation)

> **주제**: 라우터·스위치 설정을 실제로 넣기 **전에** 위험을 걸러내는 방법
> **왜 배우나**: 네트워크관리사 2급 실기 + 정보보안기사 「네트워크 보안」 파트와 직결. 실무에선 이걸 안 하면 장애가 난다.
> **복습용 노트**: 한 번 훑고 와도 이것만 읽으면 바로 이해되게 정리.

---

## 🧠 이 노트 한 눈에 (먼저 이것만 봐도 됨)

- 설정을 장비에 붙여넣기 전, **5단계 순서**로 검사한다.
- 순서에 이유가 있다: **터지는 것(파괴적 명령) → 뚫리는 것(자격증명·관리 접근) → 겹치는 것(IP 중복) → 없는 것(참조 무결성) → 안 보이는 것(로그·시간)**
- 검사는 **정규식(regex)으로 하되, 정규식을 파서로 착각하면 안 된다.** 최종 승인은 사람이 한다.
- **한 문장 요약: "설정 검증은 문법 검사가 아니라 사고 예방이다."**

---

## 🔎 쉽게 말하면

수술 전 **체크리스트**와 같다. 의사가 실력 없어서 체크리스트를 쓰는 게 아니라, **아무리 잘해도 사람은 빠뜨리기 때문에** 쓴다.

- `reload` 한 줄 → 병원 전체 정전
- SNMP community `public` → 현관문 비밀번호가 `0000`
- IP 중복 → 같은 병실 번호를 두 개 붙여놓음
- 없는 ACL을 참조 → "3번 창고에서 가져와" 했는데 3번 창고가 없음

---

## 🖐️ 검증 5단계 (순서대로)

### 1단계 — 파괴적 명령 (제일 먼저)

**넣는 순간 장애가 나는 명령**을 먼저 골라낸다. 다른 걸 아무리 잘 봐도 이게 있으면 끝이다.

| 명령 패턴 | 왜 위험한가 |
|---|---|
| `reload` | 장비 재부팅 → 즉시 다운타임 |
| `erase startup` / `erase nvram` / `erase flash` | 저장된 설정 삭제 → 재부팅하면 백지 |
| `format` | 장비 파일시스템 포맷 |
| `no router bgp` / `no router ospf` / `no router eigrp` | 라우팅 프로세스 통째로 제거 → 경로 전멸 |
| `no interface <이름>` | 인터페이스 설정 삭제 |
| `aaa new-model` | 인증 체계가 통째로 바뀜 → **자기 자신이 로그인 못 하게 될 수 있음** |
| `crypto key zeroize` / `crypto key generate` | SSH 키 교체 → 기존 SSH 세션·자동화 전부 끊김 |

> ⚠️ `aaa new-model`과 `crypto key zeroize`가 특히 악질이다. 장비는 멀쩡히 살아 있는데 **관리자가 못 들어간다.** 원격지 장비면 사람이 직접 가야 한다.

```python
import re

DANGEROUS_PATTERNS = [
    (re.compile(r"\breload\b", re.I), "reload causes downtime"),
    (re.compile(r"\berase\s+(startup|nvram|flash)", re.I), "erases persistent storage"),
    (re.compile(r"\bno\s+router\s+(bgp|ospf|eigrp)\b", re.I), "removes a routing process"),
    (re.compile(r"\baaa\s+new-model\b", re.I), "changes authentication behavior"),
    (re.compile(r"\bcrypto\s+key\s+(zeroize|generate)\b", re.I), "changes device SSH keys"),
]

def find_dangerous_commands(lines):
    findings = []
    for line_number, line in enumerate(lines, start=1):
        stripped = line.strip()
        for pattern, reason in DANGEROUS_PATTERNS:
            if pattern.search(stripped):
                findings.append({"line": line_number, "command": stripped, "reason": reason})
    return findings
```

> 💬 **`\b`** = 단어 경계(word boundary). `\breload\b` 는 `reload` 는 잡고 `preloaded` 는 안 잡는다. 이거 안 붙이면 오탐이 쏟아진다.
> 💬 **`re.I`** = 대소문자 무시(ignorecase). 장비 설정은 `Reload` 로도 쓰일 수 있다.

### 2단계 — 자격증명 · 관리 평면(Management Plane) 노출

**관리 평면**이란 장비를 *관리하기 위한* 통로다. 데이터가 흐르는 길이 아니라, **관리자가 들어가는 문**이다. 여기가 뚫리면 장비 전체가 넘어간다.

#### VTY 라인 점검 — 실무에서 가장 자주 걸리는 곳

`line vty` = 원격 접속(SSH/Telnet) 세션 설정. 3가지를 본다.

| 점검 항목 | 문제 | 올바른 상태 |
|---|---|---|
| `transport input ... telnet` | **Telnet은 평문**이다. 비밀번호가 그대로 흐른다 | `transport input ssh` 만 |
| `access-class <이름> in` 없음 | **아무 IP에서나** 관리 접속 시도 가능 | 관리망 대역만 허용하는 ACL 지정 |
| `exec-timeout` 없음 | 세션이 영원히 안 끊김 → 자리 비운 터미널이 그대로 열려 있음 | `exec-timeout 10 0` 등 명시 |

```python
def check_vty_blocks(config):
    issues = []
    for block in iter_blocks(config, "line vty"):
        if re.search(r"transport\s+input\s+.*telnet", block, re.I):
            issues.append("VTY allows Telnet; require SSH only.")
        if not re.search(r"\baccess-class\s+\S+\s+in\b", block, re.I):
            issues.append("VTY block has no inbound access-class source restriction.")
        if not re.search(r"\bexec-timeout\s+\d+\s+\d+\b", block, re.I):
            issues.append("VTY block has no explicit exec-timeout.")
    return issues
```

> ❗ **중요한 함정**: VTY 검사는 **블록 단위로 잘라서** 해야 한다. 설정 파일 전체에 정규식을 그냥 돌리면, 다른 섹션에 있는 `access-class` 를 보고 "이 VTY는 안전하다"고 오판한다. 위 코드가 `iter_blocks()` 로 먼저 쪼개는 이유가 이것이다.
>
> 블록 쪼개는 원리: Cisco 설정은 **들여쓰기로 소속을 표현**한다. `line vty 0 4` 로 시작해서, 들여쓰기 없는 줄(`!` 나 새 최상위 명령)이 나오면 그 블록이 끝난 것이다.

#### 자격증명 위생

| 발견 패턴 | 문제 |
|---|---|
| `snmp-server community public` / `private` | **기본 커뮤니티 스트링.** 스캐너가 제일 먼저 시도한다 |
| `snmp-server community <아무거나>` | SNMPv2 자체가 평문. **SNMPv3 authPriv** 를 써야 한다 |
| `ip ssh version 1` | SSHv1은 깨진 프로토콜. v2만 |
| `enable password` | 약한 암호화(Type 7, 즉시 복호화됨). **`enable secret`** 을 써야 한다 |
| `username X password ...` | 위와 동일. `username X secret ...` 으로 |

> 💬 **community string** = SNMP의 비밀번호에 해당하는 것. `public`(읽기)·`private`(쓰기)이 공장 기본값이라 그대로 두면 누구나 장비 정보를 긁어간다.
> 💬 **authPriv** = SNMPv3의 최고 보안 모드. auth(인증) + Priv(암호화) 둘 다 켠 상태.

### 3단계 — IP 중복 · 서브넷 겹침

같은 IP가 두 인터페이스에 붙거나, 서브넷이 겹치면 **라우팅이 예측 불가능**해진다.

```python
import ipaddress
from collections import Counter

def find_duplicate_ips(config):
    ips = [entry["ip"] for entry in extract_interfaces(config)]
    counts = Counter(ips)
    return sorted(ip for ip, count in counts.items() if count > 1)

def find_subnet_overlaps(config):
    networks = [ipaddress.ip_network(e["network"]) for e in extract_interfaces(config)]
    overlaps = []
    for index, left in enumerate(networks):
        for right in networks[index + 1:]:
            if left.overlaps(right):
                overlaps.append((str(left), str(right)))
    return overlaps
```

> 💬 **`ipaddress`** = 파이썬 표준 라이브러리. 설치 필요 없다. `ip_interface("192.168.1.10/255.255.255.0").network` 하면 `192.168.1.0/24` 를 돌려준다. **서브넷 계산을 손으로 하지 마라 — 이게 훨씬 정확하다.**
> 💬 **`.overlaps()`** = 두 네트워크가 조금이라도 겹치는지 판정. `10.0.0.0/8` 과 `10.1.0.0/16` 은 겹친다(후자가 전자에 포함).

### 4단계 — 참조 무결성 (있다고 하는데 없는 것)

설정에서 **이름으로 부르는 것들**이 실제로 정의돼 있는지 확인한다.

- ACL: `ip access-group MGMT-IN in` → `ip access-list ... MGMT-IN` 이 있나?
- route-map, prefix-list, class-map, policy-map도 동일
- 인터페이스: 존재하지 않는 인터페이스를 참조하고 있지 않나?

> ⚠️ **왜 위험한가**: 없는 ACL을 참조하면 장비에 따라 **전부 허용**되거나 **전부 차단**된다. 어느 쪽이든 의도와 다르다. 특히 "전부 허용"으로 동작하면 방화벽을 걸어놨다고 **착각한 채** 운영하게 된다.

### 5단계 — 운영 위생 (있어야 하는데 없는 것)

여기까지 통과했으면 사고는 안 난다. 이제 **사고가 났을 때 조사할 수 있는지**를 본다.

| 있어야 할 것 | 없으면 |
|---|---|
| `ntp server` | 장비마다 시간이 다름 → **로그 시간 순서를 못 맞춤** → 사고 조사 불가 |
| `service timestamps` | 로그에 시각이 안 찍힘 |
| `logging <서버>` | 로그가 장비 안에만 남음 → 장비가 죽거나 공격자가 지우면 증거 소멸 |
| `snmp-server group ... v3 priv` | 안전한 모니터링 경로 없음 |
| `banner login` / `banner motd` | 법적 경고 문구 부재 (무단 접근 시 법적 대응 근거가 약해짐) |

> 💡 **NTP가 보안 항목인 이유**를 시험에서 자주 묻는다. 시간이 안 맞으면 **여러 장비 로그를 시간순으로 엮을 수 없다.** 침해사고 대응(포렌식)에서 타임라인이 전부인데, 그게 무너진다.

---

## 💡 그래서 핵심

1. **검사 순서 자체가 지식이다.** 파괴적 → 자격증명 → 중복 → 참조 → 위생. 뒤에서부터 하면 앞의 사고를 못 막는다.
2. **정규식은 파서가 아니다.** 블록을 안 쪼개고 전체에 정규식을 돌리면 오판한다. 최종 승인은 사람이 한다.
3. **관리 평면이 핵심 공격면**이다. 데이터 경로만 지키고 VTY를 열어두면 의미가 없다.
4. **롤백 없는 변경은 금지.** 검증을 통과해도 변경 창(change window) + 롤백 절차 + OOB 접근 확보가 전제다.
5. **자동화의 게이트로 쓴다.** Netmiko·Ansible이 설정을 밀기 **전**에 이 검사를 돌리고, 파괴적 명령·자격증명 노출은 **fail closed**(막고 중단), 위생 항목은 warn(경고만).

---

## ⚠️ 하지 말아야 할 것 (Anti-Patterns)

- 정규식 검증을 장비 파서로 취급하기
- dry-run diff 없이 생성된 설정을 그대로 적용하기
- SNMPv2 community string을 모니터링 "요구사항"이라며 정당화하기
- VTY 블록 검사를 전체 파일 정규식으로 하기 (섹션을 넘나들며 오판)
- 방화벽 동작 확인한다고 **ACL을 꺼보기** → 대신 hit counter와 로그를 읽어라

## 📝 복습 셀프 체크 (답 가리고 맞혀보기)

1. 설정 검증 5단계 순서는? → *파괴적 명령 → 자격증명·관리평면 → IP중복/서브넷겹침 → 참조 무결성 → 운영 위생*
2. `aaa new-model` 이 특히 위험한 이유? → *인증 체계가 바뀌어 관리자 본인이 로그인 못 하게 될 수 있음*
3. VTY에서 봐야 할 3가지? → *Telnet 허용 여부 / access-class in / exec-timeout*
4. `enable password` 대신 써야 하는 것? → *`enable secret`*
5. VTY 검사를 블록 단위로 해야 하는 이유? → *전체 정규식은 다른 섹션의 access-class를 보고 안전하다고 오판함*
6. NTP가 왜 보안 항목인가? → *장비 간 시간이 안 맞으면 로그 타임라인을 못 엮어 사고 조사가 불가능*
7. 없는 ACL을 참조하면? → *장비에 따라 전부 허용/전부 차단. 방화벽을 걸었다고 착각하게 됨*
8. 자동화 게이트에서 fail closed 해야 할 항목은? → *파괴적 명령, 자격증명 노출*

> 위 8개를 막힘없이 답하면 이 노트는 이해 완료.

## 주요 용어 정리

| 용어 | 정의 |
|------|------|
| 관리 평면(Management Plane) | 장비를 관리하기 위한 접근 경로(SSH·SNMP·콘솔). 데이터 경로와 구분됨 |
| VTY (Virtual Teletype) | 원격 접속용 가상 터미널 라인. `line vty 0 4` 형태로 설정 |
| access-class | VTY에 적용하는 ACL. 어느 IP에서 관리 접속을 허용할지 제한 |
| exec-timeout | 유휴 세션 자동 종료 시간 |
| SNMP community string | SNMPv1/v2c의 인증 문자열. 평문 전송. 기본값 `public`/`private` |
| SNMPv3 authPriv | 인증 + 암호화를 모두 적용한 SNMPv3 보안 모드 |
| enable secret | 특권 모드 비밀번호를 강한 해시로 저장 (`enable password`는 약함) |
| 참조 무결성 | 설정이 이름으로 부르는 ACL·route-map 등이 실제로 정의돼 있는 상태 |
| fail closed | 검사 실패 시 통과시키지 않고 중단하는 방식 (반대: fail open) |
| dry-run | 실제 적용 없이 결과만 미리 보는 실행 |
| 변경 창(change window) | 서비스 영향을 감수하고 변경을 수행하기로 합의된 시간대 |
| OOB (Out-of-Band) | 본 네트워크와 분리된 별도 관리 접근 경로. 설정 실수로 접속이 끊겼을 때의 생명줄 |
| hit counter | ACL 규칙이 몇 번 매치됐는지 세는 카운터. 방화벽 동작 확인의 정석 |
